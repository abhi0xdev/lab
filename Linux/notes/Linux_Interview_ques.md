What is the Linux kernel and why is it important in system operations?
The Linux kernel is the core component of the operating system that directly interacts with hardware and manages system resources such as CPU, memory, and devices. It works by providing system calls that allow applications and services to communicate with the hardware through controlled interfaces. It is used because it provides process scheduling, memory management, and device abstraction that enable multiple applications to run efficiently. One limitation is that kernel bugs or misconfigurations can affect the entire system stability. In production environments, kernel updates must be tested carefully because incompatible drivers or modules can cause system failures.

What is the difference between a process and a thread in Linux?
A process is an independent program execution instance with its own memory space, while a thread is a smaller execution unit within a process that shares the same memory and resources. Processes are created using system calls like fork and exec, while threads are managed within a process using threading libraries such as pthread. Processes provide isolation which increases reliability, while threads improve performance by allowing concurrent execution with shared data. The trade-off is that threads can cause race conditions because they share memory space. In real systems, incorrect thread synchronization can lead to deadlocks or inconsistent application states.

What happens internally when you run a command in Linux?
When a command is executed, the shell first parses the command and checks whether it is a built-in command or an executable program. If it is an executable, the shell searches for it in the directories listed in the PATH environment variable and then uses fork to create a new process and exec to load the program into memory. The kernel schedules the process and allocates resources so the program can run. This mechanism allows Linux to support multitasking and process isolation. A limitation is that excessive process spawning can increase CPU overhead and context switching. In automation scripts, improper handling of background processes can leave zombie processes consuming system resources.

What are file permissions in Linux and how do they work?
File permissions in Linux control which users can read, write, or execute files and directories. Permissions are implemented using three permission sets for owner, group, and others, and they are enforced by the kernel during file access operations. They are used to ensure system security by restricting access to sensitive files and preventing unauthorized modifications. One limitation is that the traditional permission model can be too simple for complex access control requirements. In real environments, administrators often use Access Control Lists when multiple users require different permission combinations.

What is the difference between hard links and symbolic links?
A hard link is another directory entry pointing to the same inode as the original file, while a symbolic link is a separate file that contains the path to another file. Hard links work at the filesystem level and both links reference the same underlying data blocks on disk. Symbolic links work like shortcuts and can reference files across filesystems or directories. The limitation of hard links is that they cannot reference directories or files on different filesystems. In real-world deployments, symbolic links are often used for version management, but broken links can occur if the target file is moved or deleted.

What is the purpose of the /etc directory in Linux?
The /etc directory stores system-wide configuration files used by the operating system and services. When services start, they read configuration parameters from files in this directory to determine behavior such as network settings, authentication policies, and service parameters. It is used because it centralizes configuration management for the entire system. The trade-off is that incorrect configuration changes can break system services or prevent them from starting. In production environments, configuration files should be backed up or managed through version control tools like Git or configuration management systems.

What is a Linux daemon and how does it work?
A daemon is a background process that runs continuously and performs system or service-related tasks without direct user interaction. Daemons usually start during system boot through init systems like systemd and run in the background waiting for events or requests. They are used to provide services such as web servers, schedulers, logging, and networking. A limitation is that poorly configured daemons can consume excessive resources or create security vulnerabilities. In real systems, monitoring daemon logs and resource usage is important to detect failures or abnormal behavior.

What is systemd and why is it widely used?
Systemd is the default init system in many Linux distributions responsible for bootstrapping the system and managing background services. It works by reading unit files that define service configuration, dependencies, and startup behavior, allowing services to start in parallel during system boot. It is used because it improves boot performance and provides centralized service management commands such as systemctl. One trade-off is that systemd adds complexity and tightly integrates many system components. In production environments, incorrect unit configurations or dependency chains can delay system startup or prevent critical services from launching.

How does Linux handle process scheduling?
Linux uses a scheduler within the kernel to allocate CPU time to processes based on scheduling policies and priorities. The Completely Fair Scheduler distributes CPU time among processes to ensure fairness while allowing higher-priority processes to run more frequently. This mechanism allows the system to support multitasking and maintain responsiveness. A limitation is that CPU-intensive workloads can still affect system responsiveness if priorities are not configured properly. In production servers, administrators may adjust process priorities using tools like nice and renice to ensure critical services get sufficient CPU time.

What are environment variables in Linux and how are they used?
Environment variables are dynamic values that define configuration settings for processes and applications. They are stored in the process environment and inherited by child processes when new commands are executed. They are used to store information such as executable paths, configuration flags, and runtime settings. The limitation is that environment variables can expose sensitive data if not handled carefully. In real deployments, secrets like API keys should not be stored directly in environment variables without secure management solutions.

What is the difference between soft and hard resource limits in Linux?
Soft limits define the current operational limit for system resources such as open files or processes, while hard limits represent the maximum limit that a user or process can raise the soft limit to. These limits are enforced by the kernel to prevent users or applications from consuming excessive resources. They are configured using tools like ulimit or system configuration files. The trade-off is that setting limits too low can cause applications to fail under load. In production environments, file descriptor limits often need to be increased for high-traffic services like web servers.

How would you troubleshoot high CPU usage on a Linux server?
I would first identify which process is consuming CPU using tools like top or htop to observe real-time usage. Then I would inspect the process details using commands like ps or pidstat to understand its behavior and check whether it is expected workload or a runaway process. This approach helps determine whether the issue is application logic, system misconfiguration, or malicious activity. A limitation is that CPU spikes may occur only briefly and might be missed during manual monitoring. In production environments, it is best practice to use monitoring systems like Prometheus or Grafana to capture historical CPU usage patterns.

How would you investigate disk space issues in Linux?
I would start by checking filesystem usage using the df command to identify which partition is running out of space. Then I would use du to locate directories consuming the most storage and inspect large files or log directories. This process helps determine whether the issue is due to logs, temporary files, or application data growth. One limitation is that deleted files held open by processes can still consume disk space even if they are not visible in the filesystem. In real environments, restarting the affected service or process may be required to release that space.

What are inodes in Linux filesystems?
An inode is a metadata structure that stores information about a file such as ownership, permissions, timestamps, and pointers to data blocks. The filesystem uses inodes to locate and manage file data on disk rather than storing this information directly in directory entries. They are used because they separate file metadata from filenames, allowing multiple hard links to reference the same file. A limitation is that filesystems have a fixed number of inodes allocated during creation. In real systems, servers handling millions of small files can run out of inodes even if disk space is still available.

What is the difference between foreground and background processes?
A foreground process runs directly in the terminal and blocks further command execution until it completes. A background process runs independently of the terminal, allowing the user to continue executing other commands. Background execution is achieved using the ampersand operator or job control commands such as bg and fg. This is useful for running long tasks without blocking interactive sessions. The limitation is that background processes tied to a terminal may terminate when the session closes. In production automation, tools like nohup or system services are used to ensure processes continue running after logout.

How does Linux handle logging and why is it important for DevOps?
Linux systems use logging services such as rsyslog or journald to collect and store logs from system components and applications. Logs are written to structured files that can be inspected for debugging, monitoring, and auditing purposes. Logging is essential because it provides visibility into system behavior and helps diagnose failures. The trade-off is that excessive logging can consume storage and impact performance. In production environments, centralized logging systems like ELK or Loki are commonly used to aggregate and analyze logs from multiple servers.

How would you debug a service that fails to start on a Linux system?
I would first check the service status using systemctl status to identify the failure message and exit code. Then I would review the logs using journalctl to understand the root cause such as configuration errors, dependency failures, or permission issues. This process helps determine whether the problem is related to the service configuration or the underlying system environment. A limitation is that logs may not always provide enough information if debugging is disabled. In production environments, enabling verbose logging temporarily can help diagnose the issue more effectively.

What are Linux namespaces and why are they important for containers?
Linux namespaces provide isolation for system resources such as process IDs, network interfaces, and filesystems. They work by creating separate views of these resources so that processes in one namespace cannot see or interfere with processes in another namespace. This isolation mechanism is fundamental to container technologies like Docker. The advantage is that containers can run multiple isolated environments on the same host without full virtualization. A limitation is that misconfigured namespaces can still allow privilege escalation if combined with kernel vulnerabilities. In production environments, namespaces are usually combined with cgroups and security policies for stronger isolation.

What are cgroups and how do they help in resource management?
Control groups, or cgroups, are a Linux kernel feature used to limit and monitor the resource usage of groups of processes. They work by assigning processes to hierarchical groups and applying limits on CPU, memory, disk I/O, and other resources. They are used in container platforms to ensure that applications do not consume excessive system resources. The trade-off is that incorrect resource limits can cause application throttling or unexpected failures. In production environments, proper capacity planning is required before applying strict resource constraints.

How do you secure SSH access on a Linux server?
I would disable password authentication and enforce SSH key-based authentication to reduce the risk of brute-force attacks. Then I would restrict access using firewall rules or configuration settings such as allowing only specific users or IP addresses. This approach strengthens the security of remote access to servers. A limitation is that losing private keys can lock administrators out of the system if no backup access method exists. In production systems, it is best practice to rotate SSH keys regularly and enable monitoring for suspicious login attempts.
